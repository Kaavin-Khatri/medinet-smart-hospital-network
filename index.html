      Reachability now

      Aim

      Design a hospital network that is segmented, secure and easy to manage

      A hospital cannot run every computer on one flat network. Lab analysers, billing PCs, patient-record systems, visitor phones and life-support monitors have different needs, and a fault or intrusion in one place must not spread to the rest.

      Segmentation

      Seven VLANs split the hospital into separate broadcast domains. Trunks between three switches carry them all over a few cables, tagged with IEEE 802.1Q.

      Central services

      Router R1 routes between VLANs on one physical port (router-on-a-stick) and hands out addresses with DHCP. The HMS server provides DNS and the hospital web portal.

      Security

      Extended access lists stop guest phones from reaching any internal system except the public portal, and keep the records VLAN closed to everyone except doctors and servers.

      Guest Wi-Fi

      A WPA2 access point puts visitor devices on VLAN 99. They get an address and internet-style web access without ever seeing clinical traffic.

      IoT monitoring

      ICU bedside monitors and room sensors report through an IoT gateway. Alarms reach the nurse station on the same VLAN in two hops and are logged on the server.

      Resilience analysis

      The simulator cuts each cable in turn and counts who loses service, which shows where a second link or a backup router would matter most.

      Network design

      Addressing and VLAN plan

      Each department gets a /24 subnet named after its VLAN number, so 192.168.20.x is always the doctors. The gateway is always .1 on R1.

      How a packet crosses departments

      1. Doctor-PC sees the server is on another subnet, so it sends the frame to its gateway 192.168.20.1 (found with ARP).

      2. SW-Ground receives it untagged on access port Fa0/2 (VLAN 20) and forwards it up the trunk with an 802.1Q tag of 20.

      3. R1 receives it on subinterface G0/0.20, checks any inbound access list, looks up 192.168.50.0/24 and sends it out G0/0.50 tagged 50.

      4. SW-Core removes the tag and delivers it on access port Fa0/1 to the HMS server. The reply takes the same path back.

      Project modules

      Five parts of the network

      MediNet is organised into five modules, each built and tested on its own.

      Network design and inter-VLAN routingModule 1

      IP and VLAN plan, router R1 subinterfaces, DHCP pools, overall integration and testing.

      Switching and VLAN trunkingModule 2

      VLANs on the three switches, access and trunk ports, 802.1Q tagging and MAC learning.

      Servers: DNS and HMS web portalModule 3

      HMS-Server static addressing, DNS record for hms.medinet.local, the HTTP portal page.

      Guest Wi-Fi and network securityModule 4

      WPA2 access point, guest VLAN, extended access lists GUEST_IN and RECORDS_OUT.

      ICU IoT monitoring and reliabilityModule 5

      ICU monitor and nurse station, alarm flow, link-failure and single-point-of-failure analysis.
